# Architecture

Underline AI is a **client-side** Vue 3 single-page app. There is no backend:
all state, images, and the Gemini API key live in the browser. The only network
call is the request to Google's Gemini API, which the user's key authorizes
directly.

```
┌──────────────────────────────────────────────────────────────────┐
│                          Browser tab                              │
│                                                                  │
│   ┌────────┐   ┌─────────┐   ┌─────────┐   ┌─────────┐           │
│   │ Pages  │ → │  Stores │ → │Services │ → │Resources│           │
│   └────────┘   └─────────┘   └─────────┘   └─────────┘           │
│        │            │              │              │               │
│        ▼            ▼              ▼              ▼               │
│   ┌─────────┐  ┌──────────┐  ┌────────┐   ┌────────────┐         │
│   │Layouts  │  │Composab. │  │  Lib   │   │ IndexedDB  │         │
│   └─────────┘  └──────────┘  └────────┘   │  (Dexie)   │         │
│                                          └────────────┘         │
│                                                                  │
│        ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─           │
│                       https://generativelanguage.googleapis.com  │
│                                  (Gemini API, user key)          │
└──────────────────────────────────────────────────────────────────┘
```

## Layered model

The codebase is organized into strict layers. **ESLint blocks cross-layer
imports** (`eslint.config.js` defines per-folder `no-restricted-imports`
rules), so the boundaries are part of the type system, not just convention.

```
                 pages
                   │
                   ▼
          components · composables
                   │
                   ▼
                 stores
                   │
                   ▼
               services
                   │
                   ▼
              resources · lib
```

| Layer | Folder | Responsibility | May import |
|---|---|---|---|
| Pages | `src/pages/` | Route-level views, orchestrate stores/components | components, composables, stores, lib |
| Layouts | `src/layouts/` | Chrome (nav, footer, loading state) | stores, lib |
| Components | `src/components/{ui,molecules,organisms}/` | UI building blocks | lib, composables |
| Composables | `src/composables/` | Reusable reactive hooks | stores, lib |
| Stores | `src/stores/` | Pinia state, hydration, setters | services, lib |
| Services | `src/services/` | Domain logic, I/O wrappers, crypto | resources, lib |
| Resources | `src/resources/` | Data definitions, DB tables (Dexie) | lib only |
| Lib | `src/lib/` | Pure utilities, formatters, defaults | — |

The atomic-design split inside `src/components/` matches the project
convention:

- `ui/` — generated by shadcn-vue, treats as third-party primitives
- `molecules/` — small composed units (a card, a row, a header)
- `organisms/` — larger composed units (the settings form, a list item)
- `templates/` — reserved, currently empty

## Extraction data flow

The Operation page is the only place the full pipeline is wired together.

```
 FileList  ──┐
             │  OperationFileUpload
             ▼
   items: ImageItem[]           (operation-page.vue)
             │
             │  for each item, in parallel
             ▼
   ┌──────────────────────┐
   │  state = optimizing  │
   │  imageOptimizerService.optimize(file, options)
   │    → canvas resize   │
   │    → optional gray   │
   │    → JPEG/WebP re-encode
   └──────────┬───────────┘
              │ OptimizedImage { file, originalSize, optimizedSize, … }
              ▼
   ┌──────────────────────┐
   │  state = loading     │
   │  aiService.generate([file], model)
   │    → base64 encode   │
   │    → @google/genai   │
   └──────────┬───────────┘
              │ text
              ▼
   ┌──────────────────────┐
   │  state = success     │
   │  historyStore.record(HistoryEntryInput)
   │    → Dexie history table
   └──────────────────────┘
```

Per-item state is local to the page (`ImageItem.state`), so a single failed
image can be retried without touching the others.

## State management

All persistent state goes through Pinia stores. Stores never touch the
database directly — they delegate to services.

| Store | Source service | Persisted keys |
|---|---|---|
| `useGeminiStore` | `configService` + `aiService` | encrypted key, model, system prompt |
| `useOptimizerStore` | `configService` | max dimension, quality %, grayscale, format |
| `useHistoryStore` | `historyService` | run records (incl. image blobs) |

Each store exposes a `hydrate()` action. `app-layout.vue` calls `hydrate()`
on both stores during boot, then renders the layout. A
`useAppReady` composable derives `gemini.isReady && optimizer.isReady`
so individual pages don't have to.

## Routing & layouts

`src/plugins/router/routes.ts` defines four routes. Each route declares a
`meta.layout` of `'app'` or `'empty'`, and `App.vue` switches between
`AppLayout` and `EmptyLayout` based on the matched route. The
`requireApiKey` guard on `/operation` redirects to
`/settings?reason=missing-api-key` when the encrypted key is empty,
which opens a dialog explaining what to do.

```
/                  → home-page         (layout: empty)
/operation         → operation-page    (layout: app,   guard: requireApiKey)
/history           → history-page      (layout: app)
/settings          → settings-page     (layout: app)
```

## Security & privacy

- The Gemini API key is encrypted with **AES (CryptoJS)** using a hard-coded
  local salt before being written to IndexedDB. This is obfuscation, not
  real security — anyone with the bundle and the user's storage can
  recover it. Its purpose is to keep the key out of plaintext DB dumps
  and shoulder-surfing by accident.
- No analytics, no third-party scripts, no telemetry.
- The only network requests are to `generativelanguage.googleapis.com`,
  made by the user's own key.

## Build & tooling

- **Vite 8** + `@vitejs/plugin-vue`, Tailwind 4 via `@tailwindcss/vite`.
- **TypeScript** with project references (`tsconfig.json` → `tsconfig.app.json` / `tsconfig.node.json`).
- **ESLint** flat config built on `@antfu/eslint-config` with three custom blocks:
  stylistic (2-space, single quotes), arrow-functions-only, and the
  per-folder import boundaries.
- **Vitest** runs in `jsdom`; tests live next to the code they cover
  (`*.test.ts`).
- **pnpm** with `pnpm-workspace.yaml`; CI uses `pnpm install --frozen-lockfile`.
- **CI** (`.github/workflows/ci.yml`) runs `lint`, `typecheck`, `test`, `build` on every PR.

See `developer-guide.md` for how to add new code within these constraints.
